# SupplierEvidence｜供应商准入与采购证据核验 RAG 平台

## 1. 项目定位

SupplierEvidence 是面向采购准入场景的证据型 RAG 系统。用户输入供应商、采购品类和地区，系统从准入规范、合同条款、资质附件、历史评审与公开采购记录中检索证据，生成可追溯的供应商档案，并识别资料缺失、证据冲突与需要人工确认的风险项。

本项目是 **RAG 系统**，不是自主决策 Agent：模型仅负责理解材料、归纳与生成受引用约束的报告；资料完整性、有效期和准入要求采用明确、可查看的规则判断。

## 2. 一期业务边界

- 单一演示品类：工业零部件供应商准入。
- 单一演示地区：欧盟公开采购记录 + 本地模拟供应商材料。
- 供应商材料均为脱敏或模拟数据；不得对真实企业输出违法、制裁或信用结论。
- 外部公开数据以 TED（欧盟公开采购公告）为主；外部数据接入在一期可离线导入，不依赖实时联网。

## 3. 用户输入与输出

### 输入

- 供应商名称
- 采购品类
- 注册或供货地区
- 可选：拟采购金额、关键资质要求

### 输出：供应商证据档案

1. 基础档案：名称、地区、品类、证据来源数量与最后更新时间。
2. 材料覆盖：必需材料已提供、缺失、已过期或待人工核验。
3. 冲突证据：例如合同、资质附件或历史记录中的有效期、地址、认证范围不一致。
4. 风险项：由公开规则得出的提示，不等同于对企业的事实判决。
5. 证据卡片：原始来源、版本、页码/片段、检索分数、支持的结论。
6. 可追溯报告：每一项关键陈述均带引用；没有充分证据时明确写“证据不足”。

## 4. 核心链路

```text
供应商 + 品类 + 地区
  -> 数据范围过滤
  -> Hybrid Retrieval（BM25 + 向量检索 + RRF/重排）
  -> Evidence Gate（覆盖度、权威性、时效、冲突、证据不足）
  -> 结构化 RAG 报告（JSON + 引用）
  -> Output Gate（结论必须有引用；禁止超出证据）
  -> 档案页 / 风险与缺失材料清单 / 可导出报告
```

## 5. 两类分数

### 证据分（Evidence Score）

衡量系统是否有足够材料支持当前结论。分数由证据覆盖、来源权威性、时效、相互一致性和来源多样性组成。低分时系统不得给出确定性结论。

### 业务风险分（Rule-based Risk Score）

由可配置规则计算，例如必需资质缺失、证书临期、证据字段冲突或历史履约评审低于阈值。该分数是采购准入提示，不是对企业信誉或法律状态的自动判决。

## 6. 门禁设计

### Evidence Gate（生成前）

- 是否检索到对应供应商、品类和地区的证据。
- 是否覆盖当前品类的必需材料。
- 证据是否过期、来源是否可信、字段是否互相冲突。
- 证据不足时改为“待补充材料 / 待人工复核”。

### Output Gate（生成后）

- 每个关键结论是否绑定至少一张证据卡。
- 报告是否误把“待核验匹配”写成事实。
- 是否出现了检索材料未支持的风险结论。
- 不通过则退回为保守版报告并标注原因。

## 7. 一期页面

1. 供应商核验：输入供应商、品类、地区并查看报告。
2. 证据工作台：查看命中的证据卡、原文片段、来源版本与冲突标记。
3. 材料与规则：导入资质、合同、评审记录；维护必需材料与有效期规则。
4. 评测中心：固定测试集比较检索命中、冲突识别、缺失材料识别和无证据结论率。

## 8. 评测指标

- Evidence Hit@K：目标证据是否出现在前 K 条检索结果中。
- Material Missing F1：必需材料缺失识别是否准确。
- Conflict Detection Accuracy：跨文档字段冲突是否被正确发现。
- Citation Coverage：关键结论中带可用引用的比例。
- Unsupported Claim Rate：无充分证据仍生成确定结论的比例，越低越好。

## 9. 实施顺序

1. 建立供应商、文档、证据、规则、评审任务的数据模型与模拟语料。
2. 改造入库链路，保留来源、版本、页码与元数据。
3. 实现 Hybrid Retrieval 和供应商/品类/地区过滤。
4. 实现 Evidence Gate、冲突/缺失检测与结构化报告。
5. 建立证据工作台和供应商报告页。
6. 建立固定评测集与实验对比。
7. 接入 TED 离线公开数据，最后再考虑可选在线连接器。

## 10. 非一期范围

- 不做实时爬取或自动调用商业征信服务。
- 不根据模糊名称匹配直接给出制裁、违法或信用结论。
- 不做自主采购决策或自动签约。
